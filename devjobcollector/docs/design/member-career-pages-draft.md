# 회원 커리어 페이지 구현 초안

- 문서 상태: Draft
- 작성일: 2026-08-24
- 대상: DevJobs Frontend 회원 영역
- 구현 상태: 로컬 구현 및 정적 빌드 검증 완료, 커밋·배포 전
- 참고 화면:
  - `https://jumpit.saramin.co.kr/myjumpit`
  - `https://jumpit.saramin.co.kr/resumes`

## 1. 배경과 목적

기존 서비스는 로그인 성공 후 공개 메인(`/`)으로 이동하며, 로그인 회원이 자신의 채용 활동과 이력서로 진입할 수 있는 전용 시작 화면이 없었다.

이번 구현은 로그인 직후 회원 전용 랜딩 페이지를 제공하고, 해당 화면에서 `마이데브잡`과 `이력서 관리`로 이동할 수 있게 하는 것을 목표로 한다. 참고 서비스의 정보 구조는 기능적 참고로만 사용하며, 화면과 문구는 DevJobs 디자인 체계에 맞게 별도로 구성한다.

## 2. 사용자 흐름

```mermaid
flowchart LR
    A[로그인 또는 회원가입 완료] --> B[/member 커리어 홈]
    B --> C[/my-devjobs 마이데브잡]
    B --> D[/resumes 이력서 관리]
    D --> E[/resume 이력서 편집기]
    C --> F[/jobs 채용공고 탐색]
```

- OAuth 및 이메일 로그인 성공 시 기본 이동 경로를 `/member`로 변경한다.
- 로그인 전에 보호 경로로 접근하면 `/login?next=<원래 경로>`로 이동한다.
- 로그인 후 헤더는 `로그인/회원가입` 대신 `마이데브잡/로그아웃`을 노출한다.
- 로그아웃 시 액세스 토큰과 로그인 후 이동 경로를 제거하고 공개 메인으로 이동한다.

## 3. 라우트 설계

| 경로 | 화면 | 인증 | 역할 |
|---|---|---:|---|
| `/member` | 회원 커리어 홈 | 필수 | 로그인 후 랜딩 및 회원 기능 허브 |
| `/my-devjobs` | 마이데브잡 | 필수 | 저장 공고, 지원 현황, 최근 본 공고 관리 |
| `/resumes` | 이력서 관리 | 필수 | 이력서 현황 및 편집 진입 |
| `/resume` | 이력서 편집기 | 필수 | 기본 정보, 기술 스택, 프로젝트, 경력 작성 |
| `/jobs` | 채용공고 목록 | 불필요 | 회원 페이지의 공고 탐색 연결 대상 |

## 4. 화면별 초안

### 4.1 회원 커리어 홈

주요 구성은 다음과 같다.

- 회원 환영 영역과 `MY CAREER SPACE` 메시지
- 마이데브잡 바로가기 카드
- 이력서 관리 바로가기 카드
- 채용공고 탐색 CTA
- 데스크톱 사이드바 및 모바일 상단 회원 탭

핵심 행동은 페이지 진입 후 한 번의 클릭으로 마이데브잡 또는 이력서 관리 화면에 도달하도록 구성한다.

### 4.2 마이데브잡

다음 세 영역을 탭으로 제공한다.

- 저장한 공고
- 지원 현황
- 최근 본 공고

초기 구현에서는 각 영역의 수량을 `0`으로 표시하고, 데이터가 없을 때의 안내와 `/jobs` 이동 CTA를 제공한다. 실제 저장·지원·조회 이력을 연결하려면 회원별 활동 API가 추가되어야 한다.

### 4.3 이력서 관리

이력서 작성 상태를 보여주는 관리 허브로 구성한다.

- 이력서 상태 배지
- 작성 항목: 기본 정보, 기술 스택, 프로젝트, 경력
- `/resume` 편집기로 이동하는 `이력서 작성하기` 및 `이어 작성하기` 버튼
- 프로젝트 기여와 결과를 구체적으로 작성하도록 돕는 안내 영역

기존 `/resume` 편집기는 유지하고, `/resumes`가 이력서 목록·관리 역할을 담당한다.

## 5. 공통 UI 및 반응형 정책

- 기존 DevJobs 보라색 브랜드 컬러와 Pretendard 폰트를 사용한다.
- 데스크톱에서는 회원 사이드바와 본문을 2열로 배치한다.
- 900px 이하에서는 사이드바를 상단 3개 탭으로 전환한다.
- 680px 이하에서는 카드와 요약 영역을 단일 열로 전환한다.
- 모바일 하단 탭의 `이력서`는 `/resumes`, `MY`는 `/my-devjobs`로 연결한다.
- 키보드 사용자를 위해 탭에는 `role="tab"`과 `aria-selected`를 제공한다.

## 7. 데이터 연동 현황과 제한사항

| 영역 | 현재 상태 | 운영용 후속 작업 |
|---|---|---|
| 회원 프로필 | 공통 문구 `개발자님` 표시 | `/api/v1/members/me` 등 회원 조회 API 연동 |
| 저장 공고 | 빈 상태 UI | 북마크 생성·조회·삭제 API 및 DB 테이블 |
| 지원 현황 | 빈 상태 UI | 지원 단계 및 변경 이력 API |
| 최근 본 공고 | 빈 상태 UI | 회원별 최근 조회 기록 저장 정책과 API |
| 이력서 목록 | 단일 작성 카드 | 회원별 이력서 목록·상태·수정 시각 API |
| 이력서 저장 | 기존 API 사용 | 현재 `ConcurrentHashMap` 메모리 저장을 DB 영속화로 전환 |
| 인증 판별 | `localStorage` 토큰 존재 여부 | 만료 토큰 검증 및 401 공통 로그아웃 처리 |

현재 백엔드 이력서 저장소는 애플리케이션 재시작 시 데이터가 사라질 수 있으며 회원 소유권 검증도 부족하다. 따라서 이번 단계의 `/resumes`는 관리 화면 초안이며, 운영용 이력서 기능 완료로 간주하지 않는다.

- Objective: 로그인 회원이 채용 탐색과 커리어 자료 관리를 중단 없이 이어가는 경험 제공
- Key Result 1: 로그인 후 핵심 회원 기능 도달률 100%
- Key Result 2: 랜딩에서 마이데브잡·이력서 관리까지 각각 1클릭 이내 도달
- Key Result 3: 데스크톱·태블릿·모바일 주요 해상도에서 치명적 레이아웃 오류 0건

### 합격 기준

- 로그인 및 회원가입 완료 후 `/member`로 이동한다.
- 비로그인 사용자가 세 회원 경로에 접근하면 로그인 화면으로 이동한다.
- 회원 랜딩의 두 카드가 각각 `/my-devjobs`, `/resumes`로 이동한다.
- 이력서 관리 화면에서 `/resume` 편집기로 이동한다.
- 모든 화면 폭 평가셋에서 콘텐츠 중첩과 가로 스크롤이 발생하지 않는다.
- `npm run lint`, `npm run build`가 모두 종료 코드 0으로 통과한다.
- 운영 배포 후 신규 경로 3개가 각각 HTTP 200을 반환한다.

## 10. 후속 구현 제안

1. 회원 프로필 `/me` API를 연결해 이름과 활동 수를 실제 데이터로 표시한다.
2. 공고 북마크와 최근 본 공고를 회원 기준으로 영속화한다.
3. 지원 현황에 `관심 → 지원 → 과제/면접 → 최종 결과` 상태 모델을 추가한다.
4. 이력서를 MySQL에 영속화하고 JWT 회원 ID로 소유권을 검증한다.
5. 이력서 목록, 복제, 제목 수정, 삭제 기능을 추가한다.
6. 운영 배포 후 실제 GitHub 로그인부터 회원 랜딩 도달까지 E2E를 수행한다.
