# 기업 게시판 이미지 공고 수집 설계

- 목표: 수집 승인된 기업 게시판의 이미지 공고를 DJC 상세 화면에서 읽을 수 있게 한다.
- OKR 연결: 기업 채용 원문 접근성을 높여 사용자가 별도 탐색 없이 공고 내용을 확인하도록 지원한다. 전환율 목표와 기준선은 아직 정해지지 않았다.
- 목표 KPI: 평가셋의 유효한 같은 출처 본문 이미지 추출 재현율 100%, 외부 출처·본문 외 이미지 노출 0건, 조회 실패 시 기존 이미지 보존 100%.
- 평가셋: 합성 HTML 30건(정상 10, 외부 출처 10, 본문 외 이미지 10), 웰파인 공개 77번 상세 HTML 1건, 상세 이미지 실패·출처 위조·화면 크기 4종 회귀. 합성 데이터는 실제 기업 전체에 대한 대표 표본이 아니다.
- Before: 기존 수집 초안은 본문 이미지를 수집하지 않고 원문 확인 안내만 표시한다. 운영 기준 웰파인 게시판 자동 수집은 미배포다.
- After: 로컬 테스트에서 77번 HTML의 같은 출처 JPG 1건을 추출했다. 운영 등록·노출, 이용률과 정확도는 아직 미측정이다.
- 합격 기준: 합성 평가 30/30 및 실제 77번 이미지 추출 1/1, 외부 호스트·SVG 차단, 이미지 실패 시 원문 링크 제공, MySQL 마이그레이션 및 반복 저장 검증 통과. 실제 다른 기업 형식은 별도 평가 전 지원을 보장하지 않는다.

수집은 관리자 소유권 확인 후 활성화된 게시판 목록에서 시작한다. 상세 페이지는 기존 공개 DNS 검증, HTTPS, robots 정책, 리다이렉트 차단, 응답 크기와 시간 제한을 적용해 조회한다. `.board-content`의 이미지 중 상세 페이지와 정확히 같은 출처의 PNG/JPEG/WebP 주소만 최대 10개 저장한다. 상세 확인에 실패하면 이미지 정보는 `null`로 전달하여 기존 저장 이미지를 보존하고 수집 결과를 부분 성공으로 표시한다. 성공적으로 본문을 확인했지만 이미지가 없으면 빈 목록으로 갱신한다. 한 번의 동기화에서 상세 페이지는 최대 100개만 조회한다.

공개 상세 API는 저장된 주소를 순서대로 제공한다. 브라우저는 원문과 동일한 HTTPS 출처의 이미지 주소만 표시하고 `no-referrer`와 지연 로딩을 사용한다. 이미지는 기업 사이트에서 직접 제공되므로 이용자의 브라우저 IP가 해당 사이트에 전달될 수 있고, 원문 서버가 리다이렉트하면 브라우저가 다른 호스트로 이동할 수 있다. 원문 이미지 삭제·차단 시 원문 링크를 제공한다. 서버에 파일을 영구 저장하거나 임의 URL 프록시를 만들지 않는다.

OCR이나 이미지의 텍스트 추출·검색 인덱싱은 이 구현에 포함하지 않는다. 지원 자격 등 구조화된 텍스트를 추정하지 않으며, 향후 OCR을 추가할 때 정확도 평가셋과 외부 서비스 이용 여부를 별도로 정한다.
