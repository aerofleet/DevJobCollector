# HWP/HWPX 미리보기 검증 현황

- 목적: 공고 첨부를 다운로드하기 전 내용을 확인할 수 있도록 한다. 연결할 사업 목표는 지원자가 공고의 자격 조건을 확인하는 비율 개선이다. 현재 기준값과 목표치는 정해지지 않았다.
- 목표 KPI: 수집 첨부 파일의 미리보기 성공률 및 첫 페이지 표시 시간. 운영 목표·합격 수치는 미확정이다.
- 평가셋: 2026-11-10 공개 ALIO 첨부 해시 기준 고유 50건(HWP 47건, HWPX 3건), 최대 17쪽·3,914,240바이트다. 파일은 임시 디렉터리에만 보관한다.
- 측정: Chromium에서 `@rhwp/core` 0.8.6 웹 워커로 문서를 열고 각 페이지의 SVG 생성 여부를 검사했다. 50/50 파일의 모든 페이지에서 SVG 문자열이 생성됐다. 첫 페이지 처리 시간 관측 범위 234~685ms는 워커 초기화를 포함한 이 테스트 환경의 값이며, 파일 다운로드는 포함하지 않는다.
- Before/After: 운영 제품에는 HWP 미리보기가 없다. 로컬 작업 공간에 미리보기 UI와 파일 프록시를 연결했으며 아직 운영에 배포하지 않았다.
- 합격 기준: 표·병합 셀·이미지·수식·머리말/꼬리말·배포용 파일의 원본 대조와 모바일 메모리를 추가 평가하고 수치 기준을 정해야 한다. 실제 20MiB 이상 및 50쪽 이상 파일과 실패·폴백 검증 결과는 아래와 같다. 위 통과 결과만으로 운영 출시를 판정하지 않는다.
- 수집 URL: DB의 `opendata.alio.go.kr/recruit/downloadAtchFile?recrutAtchFileNo=<번호>`는 HTML을 반환한 사례가 있었다. 동일 번호의 `www.alio.go.kr/download/download.json?fileNo=<번호>`에서 해당 파일의 바이너리를 확인했다. 문서별 일치성을 추가로 확인해야 한다.
- 패키지: 0.9.0 WASM은 26,835,482바이트로 Cloudflare 정적 자산 25MiB 한도를 넘는다. 0.8.6은 9,936,164바이트이며 위 POC에 사용했다. 0.x 패키지는 버전을 고정하고 업그레이드 시 재검증한다.
- 보안: DB에 등록되고 공개 상태인 공고의 HWP/HWPX만 허용한다. 허용 호스트, 연결에 사용되는 DNS 주소, 리다이렉트를 검사하고, 30MiB 제한 및 파일 시그니처를 확인한다. 원본 파싱은 취소·타임아웃 가능한 웹 워커에서 실행하며 SVG는 스크립트가 비활성화된 샌드박스 iframe에서 표시한다. 현재 IPv6 연결은 보수적으로 차단한다. 공개 파일 레코드와 숨김·비활성·마감 공고의 접근 제한은 MySQL 26.7에서 검증했다. 실제 운영 부하·변환 품질·대형 문서 평가는 남았다.
- 운영 지표: 파일 요청, 스트리밍 성공·실패·바이트·지연, 클라이언트 렌더 성공·파싱 실패·원본 전환 카운터를 추가했다. 스트리밍 성공은 렌더 성공과 별도 지표다.
- 2026-11-10 격리 MySQL 26.7 검증: 공개 첨부는 200, 숨김·비활성·마감 공고의 첨부는 404였다. MySQL의 파일 레코드에서 시작해 실제 ALIO 원본 HWP를 프록시로 스트리밍하는 별도 로컬 실측도 성공했다. DB·웹·프록시 보안 관련 평가 12건은 실패 0건이었다.
- 브라우저 검증: 모의 API를 사용한 UI 검증 4건과 빌드 결과물에서 실제 공개 ALIO HWP를 표시하는 검증 1건이 통과했다. 모바일 화면은 360px에서 확인했다. 운영 배포 후 실측은 아직 하지 않았다.
- 격리 종단 검증: Docker MySQL 26.7의 공고·첨부 레코드, 별도 포트 Spring Boot, 실제 ALIO 파일, React 미리보기와 WASM 렌더러를 연결해 5쪽 문서의 화면 표시 및 원본 링크를 확인했다. 브라우저 1건 통과.
- 20MiB 입력 경로: 실제 HWP 뒤에 빈 바이트를 추가해 21MiB로 만든 합성 파일을 모의 API로 전달했을 때 첫 페이지 표시가 성공했다. 문서 내용이 20MiB인 실제 대형 파일의 렌더링이나 메모리 사용량을 검증한 결과는 아니다.
- 50쪽 이상 및 동시성: 공개 HWPX 문단을 복제해 만든 합성 62쪽 문서에서 첫·마지막 쪽 렌더링과 스크롤 시 최대 6개 iframe 유지가 통과했다. 모의 원본으로 21MiB 스트림 3개를 동시에 유지한 동안 4번째 스트림이 제한되고 3개가 완료됐다. 실제 운영 부하나 실제 50쪽 이상 공고에 대한 측정은 아니다.
- 공식 PDF 대조: 동일 ALIO 공고의 HWPX 양식 2쪽을 공식 PDF의 해당 2쪽과 육안 비교했다. 양쪽의 주요 텍스트와 표 구조를 확인했고 글꼴 두께·간격과 일부 선 두께 차이가 있었다. 이 1개 문서의 2쪽 비교는 전체 평가셋의 서식 일치를 보장하지 않으며, 수식·이미지·머리말 등은 별도 대조가 필요하다.
- 격리 환경 동시 요청: 실제 ALIO 파일을 대상으로 로컬 프록시에 10개 요청을 동시에 보냈을 때 3건은 200, 7건은 동시성 제한 429였다. 실행 중 health 요청 5건은 모두 200(12~18ms)이었고 이후 프록시도 200으로 응답했다. 운영 부하 시험 결과는 아니다.
- 이미지 원본 대조: [대구경북지방중소벤처기업청 공개 공고](https://www.mss.go.kr/site/daegu/ex/bbs/View.do?bcIdx=1061502&cbIdx=253)의 같은 안내문 HWPX와 PDF를 비교했다. HWPX 내부 PNG 6개가 렌더링된 3쪽의 SVG에 2·3·1개로 포함됐고 PDF의 쪽별 이미지 개수와 같았다. 첫 쪽 육안 비교에서 두 이미지와 주요 배치는 확인됐고 글꼴·간격 차이는 있었다. ALIO 원본이 아닌 렌더러 단독 평가이며, 나머지 2쪽은 이미지 개수만 확인했다.
- 추가 수집: 경험 필터 없이 최신 목록에서 HWP/HWPX 100건을 수집했다. 이전 50건과 SHA-256 기준으로 중복을 제외한 새 파일은 97건이며 추가 표본 최대 크기는 1,742,436바이트였다. Chromium 워커 평가에서 100/100 파일의 모든 페이지가 SVG를 생성했다. 실제 20MiB 이상 파일은 이 표본에서 발견하지 못했다.
- 실제 대형 파일: [서울시 공개 보도자료](https://www.seoul.go.kr/news/news_report.do?nttNo=454645)의 22,774,272바이트 HWP를 360px Chromium 화면에 모의 API로 전달했다. 공식 PDF와 동일한 7쪽을 인식하고 첫·마지막 쪽이 표시됐다. 첫 쪽 표시는 로컬 시험에서 클릭 후 2,555ms였으며 실제 네트워크 전송 시간은 포함하지 않는다. 채용공고나 ALIO 프록시를 통한 실측은 아니며 모바일 기기 메모리는 측정하지 않았다.
- 실제 장문 파일: [인천교육청 계약제교원 운영 지침](https://www.ice.go.kr/ice/na/ntt/selectNttInfo.do?mi=12308&nttSn=3350094)의 4,138,310바이트 HWPX를 모의 API로 전달했을 때 120쪽을 인식하고 첫·마지막 쪽을 표시했다. 마지막 쪽 이동 후 iframe은 6개 이하로 유지됐다. 채용공고 자체가 아닌 공개 지침이며 모든 쪽의 원본 서식은 대조하지 않았다.
