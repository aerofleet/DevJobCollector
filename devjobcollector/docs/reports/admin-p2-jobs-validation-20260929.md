# DJC 관리자 P2 공고 관리 검증

## 범위

- 관리자 세션 전용 공고 검색·페이지 목록, 상세, 숨김·복구·강제 마감 API와 SPA 화면
- `ACTIVE → HIDDEN`, `HIDDEN/CLOSED → ACTIVE`, `ACTIVE/HIDDEN → CLOSED` 전이. 재활성 시 수집 비활성 또는 만료 공고에는 새 마감일이 필요하다.
- 기대 버전과 사유를 확인하고 공고 상태·이력·관리자 감사를 한 트랜잭션에 기록
- 공개 목록·검색·상세에서 `HIDDEN`과 `CLOSED` 공고 제외. 수집원의 `is_active`와 관리자 노출 상태 분리

## KPI / OKR / 평가셋

- **OKR 연결**: 수동 DB 변경 없이 공고 노출을 조정하고 관리자 조치를 감사 가능하게 한다.
- **목표 KPI**: 공고 목록 API p95 ≤ 500ms, 숨김·마감 공고 공개 검색·목록 노출 0건, 상태 변경 성공 시 이력·감사 누락 0건, 일반 회원 JWT 관리자 API 접근 성공 0건.
- **평가셋**: 단위 상태 전이·버전 충돌·역할 차단·공개 상세 5건, 관리자 웹 인증·CSRF·버전 필수 4건, MySQL 26.7 공고 숨김→복구→마감과 공개 검색·목록 평가 1건 및 전체 DB 평가 107건, 관리자 SPA 360/768/1024/1440px 공고 숨김 E2E 4건, 목록 warm-up 3회·측정 30회.
- **Before / After**: 공고 관리 화면은 안내 자리 표시자였고 관리자 공고 API는 0개였다. 변경 후 API 3개와 공고 관리 화면 1개가 구현됐다. 공개 검색은 관리자 숨김 상태를 검사하지 않았으나 변경 후 숨김·마감 fixture가 0건 노출됐다. 목록 p95는 구현 전 측정 대상 없음 → MySQL 26.7 단일 fixture 30회에서 7ms.
- **합격 기준**: 단위·웹·MySQL·프런트 평가 실패 0건, 4개 viewport E2E 통과, 목록 p95 ≤ 500ms, 숨김·마감 공개 노출 0건.
