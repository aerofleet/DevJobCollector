# 근무형태 라벨 평가 프로토콜

기준일: 2026-11-01
상태: 평가 설계 및 탐색 표본 준비, 제품 적용 전

## 목표와 범위

- **목표 KPI(제안)**: `SI_OUTSOURCING` 및 `DISPATCH` 공개 라벨의 precision 각각 90% 이상, 검증 후 전체 대상 공고 중 자동 분류 coverage 30% 이상.
- **OKR 연결**: 개발자가 원하는 사내 제품 개발 공고를 찾고 외주·파견 공고를 직접 걸러내는 부담을 낮춘다. 사용자 검색 성공률·지원 전환 영향은 아직 측정하지 않았다.
- **현재 Before**: 탐색 표본 200건에서는 후보 규칙이 `UNKNOWN` 200건, `SI_OUTSOURCING` 0건, `DISPATCH` 0건을 출력했다. 이를 정확도 성능으로 해석하지 않는다.
- **합격 기준**: 고정된 독립 정답셋에서 공고 ≥200건 및 독립 기업 ≥30곳, 각 공개 라벨 precision ≥90%, 기업 단위 bootstrap 95% 신뢰구간 하한 ≥80%, 공개 라벨 coverage ≥30%, 각 유형별 재현율 ≥60%, 검증 hard-negative 오분류율 ≤5%. 한 기준이라도 미달하면 사용자 노출을 막는다.
- 검토자 신뢰도: raw 일치율과 Cohen's kappa를 함께 계산한다. kappa ≥0.80을 충족하지 않으면 adjudication을 마치고 라벨 가이드를 보완한 후 평가한다.

## 평가셋 정의

- 대상: 활성 개발 직군 공고. 직무 키워드 검색어, 원문 URL, 수집 시각을 기록한다.
- 크기: 최소 200건 및 독립 기업 30곳. 출처별 비율을 실제 활성 공고 분포에 맞추고, 근무형태 후보별 양성 예와 부정 예를 각각 최소 30건 포함한다. 부족하면 `미평가`로 남기며 임의로 합성 자료를 채우지 않는다.
- 라벨: `IN_HOUSE`, `SI_OUTSOURCING`, `DISPATCH`, `UNKNOWN`. `sample-work-arrangement.py`가 `reviewer_a`, `reviewer_b`, `adjudicated_label`, `evidence_quote`, `hard_negative` 입력 칸을 만든다. 두 검토자는 예측 결과를 보지 않고 독립 판정한다. `reviewer_a`/`reviewer_b`로 일치율을 측정하며 불일치는 제3 검토자가 `adjudicated_label`에 결정하고 원문 구절 및 판정 사유를 보존한다. Hard negative는 `IN_HOUSE` 또는 `UNKNOWN`으로 독립 확인된 공고이며, 이 중 하나라도 `SI_OUTSOURCING`/`DISPATCH`로 분류되면 오류로 센다.
- 누출 방지: 동일 기업·공고의 중복과 재게시를 같은 split에 둔다. 규칙 개발 표본과 최종 평가 표본을 분리하며, 최종 평가 결과를 본 뒤 규칙을 변경하면 새 평가셋을 준비한다.
- 공개 화면: `SI_OUTSOURCING`/`DISPATCH`는 별도 KPI를 통과하기 전 표시하거나 기본 필터로 사용하지 않는다. `IN_HOUSE`는 직접 사내 제품/서비스 개발 증거가 본문에 명시된 경우만 후보로 판정한다.

## 라벨 판정 가이드

| 라벨 | 필요한 본문 근거 | `UNKNOWN`으로 남길 예 |
|---|---|---|
| `IN_HOUSE` | 해당 고용 주체의 자체 서비스·제품을 직접 설계/개발/운영한다는 업무 설명 | 자체 서비스 이름만 기술 스택·경력 조건에 나옴, 고객 프로젝트와 자체 제품이 혼재 |
| `SI_OUTSOURCING` | 고용 주체가 고객사 시스템 통합·구축·유지보수 계약을 수행하고, 채용 직무가 그 납품 업무를 담당한다는 설명 | `고객사`가 영업 고객/파트너라는 문맥, 지원 자격의 “구축 프로젝트 경험”, 외주 제작 부품 언급 |
| `DISPATCH` | 파견 고용/근로 계약 또는 파견 인력으로 고객사 사업장에서 일한다는 명시적 설명 | 고객사 협업·출장·상주 가능성만 언급, 근무지와 실제 고용주 관계가 불명확 |
| `UNKNOWN` | 위 판정을 지지하는 충분한 근거가 없거나 상충 | 기본 보류 라벨이며 추정으로 대체하지 않음 |

공통 규칙: `SI`, `SM`, `상주`, `고객사`, `외주`, `인하우스` 단어 하나만으로 라벨을 정하지 않는다. 업무 내용과 고용/납품 맥락을 함께 인용한다. 모집 기업의 업종·규모만으로 SI 여부를 추론하지 않는다. 근거는 짧은 원문 구절을 `evidence_quote`에 복사하고 애매한 경우 라벨 사유를 기록한다.

## 현재 자료와 제한

- 초기 탐색 원본: 200건 (Greenhouse 93, Kakao 64, Woowahan 43; 작업 PC 로컬 임시 자료).
- 개발자 키워드 표본: 90건 (COMPANY_PAGE 44, Greenhouse 30, Kakao 14, PUBLIC_ALIO 1, Woowahan 1; 작업 PC 로컬 임시 자료).
- 검색어 확장 표본: 80건 (COMPANY_PAGE 34, Greenhouse 30, Kakao 14, PUBLIC_ALIO 1, Woowahan 1; 작업 PC 로컬 임시 자료).
- 세 파일은 정답셋이 아니다. 현재는 라벨 0건이며 표본 생성 방법도 균등확률 모집단 표본이 아니다. 검색 결과로 포함된 표현은 정답 근거로 쓰지 않는다.
- 최신 기업명 포함 확장 스냅샷은 184건·17개 회사뿐이며, 쿠팡 60건·당근 27건·토스 계열 다수로 집중되어 KPI 평가에 미달한다.
- 원문 설명은 공개 채용 API에서 받은 로컬 검토 자료다. Git에 커밋하거나 제품 데이터로 적재하지 않는다.

## 다음 측정

1. 최신 활성 공고 모집단 및 출처 분포를 목록 API로 집계한다.
2. 기업·공고 중복을 제거해 출처/직무 층화 표본 200건을 만든다.
3. 예측과 분리된 독립 라벨링 후 일치율, adjudication 비율, precision/recall/coverage 및 hard-negative 오류를 계산한다.
4. 합격 KPI 통과 시 별도 구현 계획과 UI 검토를 거친다. 이번 프로토콜 문서만으로 제품 노출을 활성화하지 않는다.
